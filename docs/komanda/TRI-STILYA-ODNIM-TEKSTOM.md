# Три стиля кода и ДРАКОН-лист

Решение учителя 15.11.2026 (журнал drakon-graf `docs/komanda/README.md` § 4). Правила целиком — teacher-workpad `docs/komanda/`: `KOD-PO-FORTOVSKI.md`, `KOD-PO-PROLOGOVSKI.md`, `KOD-PO-GRAFOVSKI.md`. Этот файл — всё одним текстом, для чата без доступа к репозиторию.

## Какой стиль когда

| Что пишешь | Стиль | Вопрос стиля |
|---|---|---|
| действия: JS, Python, Forth, служебный код вокруг Prolog | по-фортовски | как разложить |
| знания и данные: факты и правила Prolog; разметка HTML; правила CSS; данные JSON; тексты Markdown | по-прологовски | как описать |
| любую программу целиком | по-графовски | как нарисовать |

Одна программа обычно требует всех трёх: действия раскладываем, знания описываем, всё вместе рисуем ДРАКОН-листом.

## По-фортовски — как разложить

- Программа — словарь маленьких слов. Одно слово — одно действие, до 15 строк (потолок, не цель), вложенность не глубже 2.
- Имена — из словаря предмета; над каждой функцией строка по-русски «слово: что делает».
- Слои снизу вверх: верхнее слово читается как фраза и не лезет в детали нижнего.
- Данные отдельно от действий, структура данных описана явно.
- Один вход, один выход: ровно один `return`, последней строкой; без хитрых однострочников и цепочек тернарных операторов.
- При переделке поведение не меняется: сначала запиши «вход → результат», потом переделывай.
- Forth (опыт стенда WAForth, 15.11): стандартные слова пишутся заглавными (`DUP`, не `dup`); русские имена слов работают; ожидаемый результат теста пишем по реальному выводу движка, а не по догадке.

## По-прологовски — как описать

- Описывай, что верно, а не как вычислить: факты и правила лежат отдельно от поиска, ищет движок.
- В правиле не больше 3 условий; больше — выдели промежуточное отношение.
- Имена отношений — русские, из словаря предмета.
- У каждого отношения есть «пример:» (должно выводиться) и «контрпример:» (не должно).
- В знаниях нет cut (`!`), `->`, assert/retract и побочных эффектов.
- Нерекурсивное правило — первым, рекурсивный вызов — не крайним слева; ответ собирать `findall`; `\+` — только на связанных переменных.
- HTML говорит, что это, а не как выглядит; в разметке нет `style="…"` и `onclick="…"`. CSS — правила «селектор → свойства», одно правило — одна вещь; цвета и размеры — переменными; без `!important`.
- JSON — структура полей и их взаимосвязи: имена полей из словаря предмета; у объектов одного вида один набор полей; связь — явное поле-ссылка, а не вложенная копия; в JSON нет действий и вычисляемого; структура рисуется в ДРАКОН-ГРАФ.
- Markdown говорит, что это (заголовок, список, блок кода), а не как выглядит; ограды блоков закрыты; блок с оградой внутри стоит в ограде длиннее.

## По-графовски — как нарисовать

- Факт — связь с подписью: `родитель(иван, петр).` = связь Иван -> Пётр: родитель.
- Правило — строка «…, если … и …» и ДРАКОН-схема «как проверяется».
- Запрос — запоминатель с пустым ответом (`кто -> ?`), ответ — те же запоминатели с ответом.
- Туда и обратно: по коду рисуется ДРАКОН-лист, по листу восстанавливается тот же код. Чего нет на листе — того нет в коде, и наоборот.

## ДРАКОН-лист

Обычный Markdown-файл рядом с кодом. В нём по порядку:

- блок ```` ```дракон ```` — порядок действий (текстовая запись схем: drakon-graf `docs/drakon/текстовая_запись.md`, копия — teacher-workpad `docs/komanda/drakon-zapis.md`);
- блок ```` ```конспект ```` (английское имя — `drakon-graf`) — данные, факты и правила на языке ДРАКОН-ГРАФ;
- тест — строки `пример:` (что должно получаться) и `контрпример:` (что не должно).

Образец — teacher-workpad `docs/komanda/primery/drakon-list-evklid.md`. Текст в иконах пиши на целевом языке (как в образце): тогда из блока `дракон` получается работающий код.

## Что сдавать в конце работы

1. Код.
2. ДРАКОН-лист к нему.
3. «Пополнение словаря»: `имя — слой (нижний/средний/верхний) — что делает — из каких слов собрано`; для Prolog — «пополнение словаря отношений»: `имя — участники — что значит — из каких отношений собрано`.

## Проверка (в teacher-workpad)

- ДРАКОН-лист: `node tools/drakon-list.mjs лист.md` — все блоки без ошибок; `--kod python` (также `kumir`, `c`, `1c`) печатает код по блокам `дракон`.
- Тест: запусти код на строках `пример:` и `контрпример:` — пример получается, контрпример нет.
- Prolog: стенд drakon-graf `site/experiments/prolog/` (кнопки стенда: «Совпало 20 из 20», «Порождение → разбор: 21 из 21», «Ошибки вложенности совпали», «Знания»: пример ✓, контрпример ✓; без рук — `python3 tools/prolog-stend.py`); Forth: `node site/experiments/forth/run-node.cjs` (20 из 20).

## Чего пока нет (не обещать)

- Страницы, которая рисует оба блока листа вместе (редактор «Живой конспект» — пока ТЗ).
- Автоматического пути «код JS или Forth → ДРАКОН-схема» и «правило Prolog → ДРАКОН-схема проверки»: рисуем руками.
- ДРАКОН-листов для сложных задач: проверен один, «Алгоритм Евклида».

YAML и Shell — вне навыка: менять только по отдельному заданию и после проверки.

Не знаешь или не нашёл в файлах — пиши «не знаю, надо проверить». Про реальный мир (оборудование, сеть, группы) сначала спроси учителя.

# Приложение 1. Правила дословно

```
ПРАВИЛО: КОД «ПО-ФОРТОВСКИ»

Весь новый и изменяемый код (JS, Python и любой другой, кроме Prolog) пиши
в стиле Forth: программа — это словарь маленьких слов, из которых
складываются большие.

1. Одно слово — одно действие. Функция делает одну вещь и помещается
   на экран: ориентир до 15 строк, без вложенности глубже 2 уровней.
   Если функция растёт — раздели её на слова поменьше.

2. Имена — из словаря предметной области. Существительные — данные
   (scheme, icon, branch, shampur, fork, loop), глаголы — действия
   (draw, connect, check, place). Над каждой функцией одна строка
   комментария по-русски: «слово: что делает».
   Пример (JS):     // развилка: рисует икону «вопрос» и два выхода
   Пример (Python): # круги: сколько кругов стража положено артефакту

3. Слои снизу вверх. Нижние слова — простые операции, средние собраны
   из нижних, верхние читаются почти как фраза:
   drawScheme = placeIcons → connectIcons → drawShampur.
   Слово верхнего уровня не лезет в детали нижнего.

4. Данные отдельно от действий. Структуры данных описывай явно
   (объект-образец, JSDoc-тип, в Python — комментарий-образец или
   dataclass), чтобы их можно было нарисовать в ДРАКОН-ГРАФ.
   Функции не прячут данные в замыканиях без нужды.

5. Каждое слово — будущая ДРАКОН-схема. Пиши так, чтобы функцию можно
   было без натяжек нарисовать одной схемой: один вход, один выход
   (ровно один return — последней строкой; ответ известен раньше —
   положи его в переменную, развилка ведёт к концу),
   ветвления и циклы простые, без хитрых однострочников, без
   цепочек тернарных операторов (в Python — без вложенных генераторов
   и условных выражений в одну строку).

6. Без хитрости. Понятность важнее краткости. Никаких регулярок-монстров
   без комментария, никаких «умных» трюков. Повторяется 2 раза —
   стоит выделить слово.

7. При переделке существующего кода поведение не меняется. Сначала
   зафиксируй, как работает сейчас (пример входа → результат), потом
   переделывай и проверяй, что результат тот же.

8. В конце работы выдай «пополнение словаря»: список новых или
   изменённых слов в формате
   имя — слой (нижний/средний/верхний) — что делает — из каких слов собрано.
```

```
ПРАВИЛО: КОД «ПО-ПРОЛОГОВСКИ»

Описывай, что верно, а не как вычислить. Знания — факты и правила —
лежат отдельно от поиска ответа: ищет движок, а не ты.

1. В правиле не больше 3 условий. Больше — выдели промежуточное
   отношение (то же «маленькое слово», что в Forth).

2. Имена отношений — русские, из словаря предмета.

3. У каждого отношения — хотя бы один «пример:» (должно выводиться)
   и один «контрпример:» (не должно).

4. В знаниях — без cut (!), assert/retract и побочных эффектов.
   Служебный код (ввод-вывод, JSON) — отдельно и «по-фортовски».

5. В конце работы — «пополнение словаря отношений»:
   имя — участники — что значит — из каких отношений собрано.
```

```
ПРАВИЛО: «ПО-ГРАФОВСКИ»

Каждое отношение рисуется в ДРАКОН-ГРАФ.

1. Факт — связь с подписью; подпись — имя отношения.
   родитель(иван, петр).  =  связь Иван -> Пётр: родитель

2. Правило — строка «…, если … и …» и ДРАКОН-схема «как проверяется»:
   условия — иконы «Вопрос» подряд по шампуру; несколько правил
   одного имени — ветки силуэта; поиск («найти такого Б») — цикл
   «Для каждого»; ответ — конец схемы.
   ГРАФ — что верно, ДРАКОН — как проверяется.

3. Запрос — запоминатель с пустым ответом (кто -> ?); ответ Prolog —
   те же запоминатели с ответом (кто -> Иван).

4. Туда и обратно — ДРАКОН-листом. Программа рисуется одним
   ДРАКОН-листом: порядок действий — ДРАКОН, данные, факты и
   правила — ДРАКОН-ГРАФ, тест — «пример:» и «контрпример:».
   Пиши код так, чтобы по нему рисовался этот лист, а по листу
   восстанавливался тот же код: чего нет на листе — того нет
   в коде, и наоборот.
```

# Приложение 2. Как писать ДРАКОН-лист

## Шпаргалка: блок `дракон`

Одна строка — одна икона; вложение — сдвигом на 2 пробела; ключевое слово — в начале строки, с двоеточием; строка без ключевого слова — действие; `# …` — пояснение автора.

| Запись | Икона |
|---|---|
| `название:` | заголовок схемы |
| обычная строка | действие |
| `вопрос:` (или `если:`), под ним `да:` и `нет:` — обе ветки обязательны | вопрос |
| `выбор:`, под ним не меньше двух `вариант:` | выбор |
| `пока:` + тело со сдвигом | цикл «пока» |
| `делать:` + тело, затем `пока:` | цикл с вопросом внизу |
| `для:` + тело | цикл «для» |
| `ввод:`, `вывод:` | ввод, вывод |
| `комментарий:` | комментарий |
| `выход из цикла`, `к следующему шагу`, `конец` | переходы |
| `ветка:` | ветка силуэта |

Пока не работают: `вставка:`, `пока нет:`, `до:`, адреса `→ Имя ветки`, параллельные действия, время.

## Шпаргалка: блок `конспект`

| Запись | Что рисует |
|---|---|
| `тема: …` | заголовок |
| `указатель -> ответ` | запоминатель: вопрос и ответ |
| `- пункт` | пункт списка (со сдвигом — внутри запоминателя) |
| `связка: А \| Б` и строки `признак -> а \| б` | таблица-сравнение (шеренга) |
| `пример: …` | пример |
| `стрелка: …` | стрелка вниз и вывод |
| `# …` | пояснение автора, на рисунок не попадает |

## Шпаргалка: блок `конспект` в режиме знаний

Для фактов и правил (расширенная часть языка; школьнику знать не нужно). Проверено на стенде Prolog 15.11.2026.

```конспект
тема: Родословная
режим: знания
Х -> ?
У -> ?
З -> ?
связь Иван -> Пётр: родитель
связь Пётр -> Анна: родитель
правило: Х предок З, если Х родитель З
правило: Х предок З, если Х родитель У и У предок З
пример: Иван предок Анны
контрпример: Анна предок Ивана
запрос: кто предок Анны
```

- `режим: знания` — включает режим; `Х -> ?` — переменная (запоминатель с пустым ответом), объявить каждую. Переменные — русские Х, У, З (дальше — Ц, Ш…); А, Б, В и латинские буквы не брать: на вид они не отличаются от латинских букв и цифр (`A`, `B` — участники, а не переменные).
- `связь Иван -> Пётр: родитель` — факт `родитель(иван, петр)`.
- `правило: …, если … и …` — правило; `пример:` должно выводиться, `контрпример:` — нет; `запрос:` — вопрос к базе (`кто`, `что`, `кого` — переменные сами по себе).
- Пока умеет только отношения двух участников («кто отношение кого»), без «или» и «не».

# Приложение 3. Образец ДРАКОН-листа (проверен 15.11.2026)

````markdown
# ДРАКОН-лист: алгоритм Евклида (проба)

Проба 15.11.2026. ДРАКОН-лист — обычный Markdown: порядок действий — блок `дракон`, данные — блок `конспект`, тест — `пример:` и `контрпример:`. Правило — `../KOD-PO-GRAFOVSKI.md`, п. 4.

## Действия

```дракон
название: НОД по Евклиду
ввод: a
ввод: b
пока: b != 0
  ost = a % b
  a = b
  b = ost
вывод: a
```

## Данные

```конспект
тема: Трассировка: НОД(48, 18)
связка: a | b | остаток
Шаг 1 -> 48 | 18 | 12
Шаг 2 -> 18 | 12 | 6
Шаг 3 -> 12 | 6 | 0
стрелка: Остаток 0 — ответ: НОД = 6
```

## Тест

- пример: ввод 48 и 18 → вывод 6
- контрпример: ввод 48 и 18 → вывод 12
````
