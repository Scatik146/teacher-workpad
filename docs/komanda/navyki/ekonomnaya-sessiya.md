# Экономная сессия

Учитель платит лимитом. Дорого стоят: чтение больших файлов и книг, скриншоты, повторные запуски браузера, длинная история разговора.

## Проекты: где состояние и свои правила

| проект claude.ai | репозиторий | состояние (читать в начале, обновлять в конце) | свои правила |
|---|---|---|---|
| «Разработка уроков», «Живой конспект», чаты по урокам | `teacher-workpad`, `drakon-graf`, `ii-komanda` | `drakon-graf/docs/komanda/SOSTOYANIE.md`; день — `BRIFING.md` там же | `teacher-workpad/CLAUDE.md`; журнал решений — `drakon-graf/docs/komanda/README.md`, разделы 4–5 |
| «Коми-пермяцкий игровой календарь» | `komi-perm-game-calendar` | `docs/proekt.md`, раздел «Планы» (только его — через grep/sed); утверждённые решения — `docs/kalendar.md` | слова — только проверяемые по словарям Баталовой и Кривощёковой-Гантман (1985) или Лыткина (1952); русский — первым и выделен; сканы книг не хранить; `docs/` = документы проекта (изменил файл в `docs/` — обновить тот же документ проекта); перед push — `npm test` и проверка сайта; новое — сначала согласовать с автором. Брифинг drakon-graf календаря не касается |
| другой проект | — | спросить учителя; если файла состояния нет — предложить завести (не длиннее страницы) | правила проекта (его документы, `CLAUDE.md` репозитория) |

## Начало
0. Определить проект (по проекту claude.ai или репозиторию) — строка таблицы выше.
1. Уроки: день начинается с чата «Брифинг» (`drakon-graf/docs/komanda/BRIFING.md`: стартовое сообщение, журнал, повестка). Рабочие чаты — по одной задаче, их итог одной строкой — в `BRIFING.md` под датой.
2. Склонировать только нужный репозиторий (`--depth 1`).
3. Прочитать **только** файл состояния своего проекта. Журналы решений, разборы (`docs/research` и т. п.) — только нужный раздел, через grep.
4. Спросить или сформулировать **одну задачу сессии** и критерий «готово». Новая большая тема — в следующую сессию, предложить записать её в «Следующие шаги» / «Планы».

## Во время работы
- Читать файлы кусками (grep, sed -n), не целиком. Не выводить большие файлы и логи в разговор.
- Скриншот: один на проверку, масштаб 0.5, обрезать нужную область. Сначала проверки командами и тестами (`tools/*.mjs`, `npm test`), скриншот — последним.
- Чтение книг, статей, чужих репозиториев, рутинный код по готовому описанию, тексты для детей — **делегировать**: написать задание по шаблону `teacher-workpad/docs/komanda/zadaniya/SHABLON.md` (уроки — файлом `zadaniya/NNN-имя.md`; другие проекты — тем же шаблоном текстом в чате) и отдать учителю для помощника. Claude оставляет себе архитектуру, решения, проверку чужих PR.
- Распределение по помощникам — в `drakon-graf/docs/komanda/README.md`.
- Короткие ответы учителю: итог и вопросы, без пересказа шагов.

## Конец (обязательно)
1. Обновить файл состояния своего проекта (не длиннее страницы): что сделано, следующие шаги. Календарь — раздел «Планы» в `docs/proekt.md` и тот же документ проекта.
2. Решения учителя: уроки — строкой в журнал `README.md`, раздел 4; открытые вопросы — раздел 5. Календарь — в свой файл `docs/` (утверждённое — `docs/kalendar.md`) и тот же документ проекта.
3. Если менялись навыки — копии в teacher-workpad `docs/komanda/navyki/` и в ii-komanda `rezerv/navyki/`, и предложение обновить навык. Эти репозитории открытые: память туда **не класть** — она только в `memory_maryam_ai` (шаг 4).
4. **Всегда, в любом проекте, если менялись навыки или память** — обновить приватный репозиторий `Scatik146/memory_maryam_ai` (главная резервная копия): навыки — `navyki/<имя>/SKILL.md`, общая память — `pamyat/obshchaya/`, память проекта — `pamyat/proekt-<название-латиницей>/` (дословно, та же раскладка; из чата проекта видна память этого проекта и общая), при новой папке — строка в таблицу «Что здесь» в `README.md`. Без паролей, ключей и данных учеников. Коммит «Память: …» / «Навыки: …».
5. Всё отправить в GitHub; в ответе — что сделано и что ждёт решения.
