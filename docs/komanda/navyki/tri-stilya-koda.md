# Три стиля кода и ДРАКОН-лист

Решение учителя 15.11.2026 (журнал drakon-graf `docs/komanda/README.md` § 4). Правила целиком — teacher-workpad `docs/komanda/`: `KOD-PO-FORTOVSKI.md`, `KOD-PO-PROLOGOVSKI.md`, `KOD-PO-GRAFOVSKI.md`. Нет доступа к репозиторию — всё одним текстом: `docs/komanda/TRI-STILYA-ODNIM-TEKSTOM.md`.

## Какой стиль когда

| Что пишешь | Стиль | Вопрос стиля |
|---|---|---|
| действия: JS, Python, Forth, служебный код вокруг Prolog | по-фортовски | как разложить |
| знания и данные: факты и правила Prolog; разметка HTML; правила CSS; данные JSON; тексты Markdown | по-прологовски | как описать |
| любую программу целиком | по-графовски | как нарисовать |

Одна программа обычно требует всех трёх: действия раскладываем, знания описываем, всё вместе рисуем ДРАКОН-листом.

## По-фортовски — как разложить

- Программа — словарь маленьких слов. Одно слово — одно действие, до 15 строк (потолок, не цель), вложенность не глубже 2.
- Имена — из словаря предмета; над каждой функцией строка по-русски «слово: что делает».
- Слои снизу вверх: верхнее слово читается как фраза и не лезет в детали нижнего.
- Данные отдельно от действий, структура данных описана явно.
- Один вход, один выход: ровно один `return`, последней строкой; без хитрых однострочников и цепочек тернарных операторов.
- При переделке поведение не меняется: сначала запиши «вход → результат», потом переделывай.
- Forth (опыт стенда WAForth, 15.11): стандартные слова пишутся заглавными (`DUP`, не `dup`); русские имена слов работают; ожидаемый результат теста пишем по реальному выводу движка, а не по догадке.

## По-прологовски — как описать

- Описывай, что верно, а не как вычислить: факты и правила лежат отдельно от поиска, ищет движок.
- В правиле не больше 3 условий; больше — выдели промежуточное отношение.
- Имена отношений — русские, из словаря предмета.
- У каждого отношения есть «пример:» (должно выводиться) и «контрпример:» (не должно).
- В знаниях нет cut (`!`), `->`, assert/retract и побочных эффектов.
- Нерекурсивное правило — первым, рекурсивный вызов — не крайним слева; ответ собирать `findall`; `\+` — только на связанных переменных.
- HTML говорит, что это, а не как выглядит; в разметке нет `style="…"` и `onclick="…"`. CSS — правила «селектор → свойства», одно правило — одна вещь; цвета и размеры — переменными; без `!important`.
- JSON — структура полей и их взаимосвязи: имена полей из словаря предмета; у объектов одного вида один набор полей; связь — явное поле-ссылка, а не вложенная копия; в JSON нет действий и вычисляемого; структура рисуется в ДРАКОН-ГРАФ.
- Markdown говорит, что это (заголовок, список, блок кода), а не как выглядит; ограды блоков закрыты; блок с оградой внутри стоит в ограде длиннее.

## По-графовски — как нарисовать

- Факт — связь с подписью: `родитель(иван, петр).` = связь Иван -> Пётр: родитель.
- Правило — строка «…, если … и …» и ДРАКОН-схема «как проверяется».
- Запрос — запоминатель с пустым ответом (`кто -> ?`), ответ — те же запоминатели с ответом.
- Туда и обратно: по коду рисуется ДРАКОН-лист, по листу восстанавливается тот же код. Чего нет на листе — того нет в коде, и наоборот.

## ДРАКОН-лист

Обычный Markdown-файл рядом с кодом. В нём по порядку:

- блок ```` ```дракон ```` — порядок действий (текстовая запись схем: drakon-graf `docs/drakon/текстовая_запись.md`, копия — teacher-workpad `docs/komanda/drakon-zapis.md`);
- блок ```` ```конспект ```` (английское имя — `drakon-graf`) — данные, факты и правила на языке ДРАКОН-ГРАФ;
- тест — строки `пример:` (что должно получаться) и `контрпример:` (что не должно).

Образец — teacher-workpad `docs/komanda/primery/drakon-list-evklid.md`. Текст в иконах пиши на целевом языке (как в образце): тогда из блока `дракон` получается работающий код.

## Что сдавать в конце работы

1. Код.
2. ДРАКОН-лист к нему.
3. «Пополнение словаря»: `имя — слой (нижний/средний/верхний) — что делает — из каких слов собрано`; для Prolog — «пополнение словаря отношений»: `имя — участники — что значит — из каких отношений собрано`.

## Проверка (в teacher-workpad)

- ДРАКОН-лист: `node tools/drakon-list.mjs лист.md` — все блоки без ошибок; `--kod python` (также `kumir`, `c`, `1c`) печатает код по блокам `дракон`.
- Тест: запусти код на строках `пример:` и `контрпример:` — пример получается, контрпример нет.
- Prolog: стенд drakon-graf `site/experiments/prolog/` (кнопки стенда: «Совпало 20 из 20», «Порождение → разбор: 21 из 21», «Ошибки вложенности совпали», «Знания»: пример ✓, контрпример ✓; без рук — `python3 tools/prolog-stend.py`); свой `.pl` без рук — `python3 tools/prolog-zapusk.py программа.pl --zapros "запрос"` (swipl-wasm в Chrome без окна; нужны google-chrome и Python playwright; `--json` — для скриптов; `zacikleno` — запрос не кончился за 5 млн шагов); Forth: `node site/experiments/forth/run-node.cjs` (20 из 20).

## Чего пока нет (не обещать)

- Страницы, которая рисует оба блока листа вместе (редактор «Живой конспект» — пока ТЗ).
- Автоматического пути «код JS или Forth → ДРАКОН-схема» и «правило Prolog → ДРАКОН-схема проверки»: рисуем руками.
- ДРАКОН-листов для сложных задач: проверен один, «Алгоритм Евклида».

YAML и Shell — вне навыка: менять только по отдельному заданию и после проверки.

Не знаешь или не нашёл в файлах — пиши «не знаю, надо проверить». Про реальный мир (оборудование, сеть, группы) сначала спроси учителя.
