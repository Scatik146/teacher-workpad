# Правило: код «по-прологовски» — как описать

Решение учителя 15.11.2026 (брифинг утро, журнал drakon-graf `docs/komanda/README.md` § 4): три стиля кода — «по-фортовски» (как разложить, `KOD-PO-FORTOVSKI.md`), **«по-прологовски» (как описать, этот файл)**, «по-графовски» (как нарисовать, `KOD-PO-GRAFOVSKI.md`).

Выделено 15.11 из `KOD-PO-GRAFOVSKI.md` без изменения смысла: пункты 1–5 ниже — прежние пункты 4–8 того файла, ловушки и раздел «Движок» перенесены дословно. Новое здесь — только общий принцип (из решения учителя) и раздел про HTML и CSS.

Действует для Prolog во всех проектах; по природе так же устроены HTML и CSS (см. ниже).

```
ПРАВИЛО: КОД «ПО-ПРОЛОГОВСКИ»

Описывай, что верно, а не как вычислить. Знания — факты и правила —
лежат отдельно от поиска ответа: ищет движок, а не ты.

1. В правиле не больше 3 условий. Больше — выдели промежуточное
   отношение (то же «маленькое слово», что в Forth).

2. Имена отношений — русские, из словаря предмета.

3. У каждого отношения — хотя бы один «пример:» (должно выводиться)
   и один «контрпример:» (не должно).

4. В знаниях — без cut (!), assert/retract и побочных эффектов.
   Служебный код (ввод-вывод, JSON) — отдельно и «по-фортовски».

5. В конце работы — «пополнение словаря отношений»:
   имя — участники — что значит — из каких отношений собрано.
```

Как каждое отношение нарисовать (факт, правило, запрос) — `KOD-PO-GRAFOVSKI.md`.

Пп. о cut/assert (п. 4) — на проверке у GLM (Зануда), см. журнал § 4, строка «Prolog „по-графовски“».

## Ловушки: «если … то будет …» (брифинг 15.11 ночью)

Правило — для того, кто пишет; симптом — для того, кто чинит.

- **Если** рекурсивное правило стоит перед нерекурсивным или рекурсивный вызов — первым условием (`предок(А,В) :- предок(А,Б), …`) → **то** запрос уходит в бесконечный цикл, браузер не отвечает. Нерекурсивное правило — первым, рекурсивный вызов — не крайним слева.
- **Если** у движка нет лимита глубины → **то** любая ошибка в правиле вешает страницу. Лимит глубины и сообщение «пошли по кругу — проверь правило».
- **Если** ответ собирать `bagof`/`setof` → **то** при отсутствии ответов запрос падает, карточка «кто -> ?» не появится. Для ответа — `findall` (пустой список = «никого»).
- **Если** `\+` применить к условию с несвязанной переменной → **то** ответ неверный. `\+` — только на связанных переменных.
- **Если** считать правила множеством → **то** удивит, что порядок меняет вывод. Порядок правил = порядок попыток.
- **Если** факта нет в базе → **то** Prolog ответит «нет» (закрытый мир: нет страуса — «страус не летает» истинно). В подписи к картинке — «не нашли = нет».
- **Если** в знаниях `!`, `->`, assert/retract → **то** схема правила перестаёт совпадать с тем, что делает Prolog. Запрещены.

## Движок (брифинг 15.11 ночью)

Prolog — внутренний движок ДРАКОН-ГРАФа (разбор, проверка, вывод, «режим знаний»), не предмет для детей. Рисование, кнопки, события, сохранение — JS. Один хозяин на функцию: перенесли в Prolog — JS-копию убрать после первого прошедшего урока (до того — тень). Движок — в Web Worker, урок работает и без него. К движку — один вызов на действие пользователя; большие строки через границу wasm не гонять. Выбор движка — замером на школьном компьютере с нашего сайта. Заморозить, если: разбор большого конспекта > 3–5 с или падение; ошибку движка чиним дольше, чем на JS; «режим знаний» не дошёл до настоящего урока к сроку стоп-проверки.

Полный список признаков заморозки (четыре, срок 20.12.2026) — журнал § 4, строка «Заморозка Prolog-движка».

## HTML и CSS — по-прологовски по природе

Решение учителя 15.11: «CSS и HTML — по-прологовски по природе: правило „селектор → свойства“, разметка „что это“».

**Как это решение читать в коде** (предложение Марьям; учитель просмотрел 15.11: «пока всё верно»; окончательно — после теста навыка на команде):

- HTML говорит, **что это**, а не как выглядит: теги и классы — по смыслу (`<nav>`, `<button>`, `class="zadanie"`), не по виду (`class="krasnyj-sleva"`).
- В разметке нет ни стилей (`style="…"`), ни действий (`onclick="…"`): вид — в CSS, действия — в JS «по-фортовски».
- CSS — набор правил «селектор → свойства»: селектор называет, **что это** (слово из словаря предмета), свойства — как оно выглядит. Одно правило — одна вещь.
- Данные вида (цвета, размеры, шрифты) — отдельно, переменными (`--cvet-ramki`), как «данные отдельно от действий».
- Не полагаться на порядок правил и не перебивать `!important`: если правило побеждает только потому, что стоит ниже, — это та же ловушка, что «порядок правил меняет вывод».
