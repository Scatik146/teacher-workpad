# Правило: код «по-фортовски»

Решение учителя 14.11.2026. Действует для всей новой разработки и всех переделок кода — teacher-workpad, drakon-graf, ii-komanda, «Живой конспект» и связанные проекты — **на любом языке** (JS, Python и другие), **кроме Prolog** (см. ниже). Копия — в проекте Claude «Живой конспект» (`claude/kod-po-fortovski.md`). Текст можно вставлять в задачу любому помощнику.

```
ПРАВИЛО: КОД «ПО-ФОРТОВСКИ»

Весь новый и изменяемый код (JS, Python и любой другой, кроме Prolog) пиши
в стиле Forth: программа — это словарь маленьких слов, из которых
складываются большие.

1. Одно слово — одно действие. Функция делает одну вещь и помещается
   на экран: ориентир до 15 строк, без вложенности глубже 2 уровней.
   Если функция растёт — раздели её на слова поменьше.

2. Имена — из словаря предметной области. Существительные — данные
   (scheme, icon, branch, shampur, fork, loop), глаголы — действия
   (draw, connect, check, place). Над каждой функцией одна строка
   комментария по-русски: «слово: что делает».
   Пример (JS):     // развилка: рисует икону «вопрос» и два выхода
   Пример (Python): # круги: сколько кругов стража положено артефакту

3. Слои снизу вверх. Нижние слова — простые операции, средние собраны
   из нижних, верхние читаются почти как фраза:
   drawScheme = placeIcons → connectIcons → drawShampur.
   Слово верхнего уровня не лезет в детали нижнего.

4. Данные отдельно от действий. Структуры данных описывай явно
   (объект-образец, JSDoc-тип, в Python — комментарий-образец или
   dataclass), чтобы их можно было нарисовать в ДРАКОН-ГРАФ.
   Функции не прячут данные в замыканиях без нужды.

5. Каждое слово — будущая ДРАКОН-схема. Пиши так, чтобы функцию можно
   было без натяжек нарисовать одной схемой: один вход, один выход
   (return в конце; ранний выход — только как явная развилка),
   ветвления и циклы простые, без хитрых однострочников, без
   цепочек тернарных операторов (в Python — без вложенных генераторов
   и условных выражений в одну строку).

6. Без хитрости. Понятность важнее краткости. Никаких регулярок-монстров
   без комментария, никаких «умных» трюков. Повторяется 2 раза —
   стоит выделить слово.

7. При переделке существующего кода поведение не меняется. Сначала
   зафиксируй, как работает сейчас (пример входа → результат), потом
   переделывай и проверяй, что результат тот же.

8. В конце работы выдай «пополнение словаря»: список новых или
   изменённых слов в формате
   имя — слой (нижний/средний/верхний) — что делает — из каких слов собрано.
```

## Prolog — своё правило

Для Prolog — правило «по-графовски» (решение 15.11): `KOD-PO-GRAFOVSKI.md` — каждое отношение рисуется в ДРАКОН-ГРАФ, у правила — ДРАКОН-схема проверки.

## Переделка старого кода

Неспешно: модуль переводится на правило, когда его трогают ради новой функции (пример — `ii-komanda/tools/ii.py` 0.2: новые слова по правилу, код 0.1 тронут только там, где требовала задача).
